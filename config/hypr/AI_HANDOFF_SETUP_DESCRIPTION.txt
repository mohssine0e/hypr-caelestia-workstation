Current CalendarEvents service behavior:
- Events are keyed by date: YYYY-MM-DD.
- Events are stored as local JSON.
- addEvent(date, title) adds an event.
- removeEvent(date, index) removes one event.
- listFor(date) returns events.
- hasEvents(date) returns whether a day has events.

Important code shape:

    readonly property string storagePath: `${Paths.state}/calendar-events.json`

    function addEvent(date, title) {
        const dateKey = key(date);
        const nextEvents = JSON.parse(JSON.stringify(events));
        if (!nextEvents[dateKey])
            nextEvents[dateKey] = [];
        nextEvents[dateKey].push({ title: cleanTitle, createdAt: Date.now() });
        events = nextEvents;
        save();
    }

    function save() {
        storage.setText(JSON.stringify(events));
    }

Local calendar events are intentionally lightweight. They are not Google Calendar.

Why not Google Calendar by default:
- Needs auth/token storage.
- Adds network sync and failure cases.
- Heavier and less private.
- Could be added later as optional manual sync, but local JSON is better for now.

Current philosophy:

- Workflow: Capture -> break into subtasks if needed -> complete.
- No categories.
- No priority.
- No notes.
- No Today/Tomorrow/Later buckets.

Two inferred task types:

1. Simple task
   - Has no subtasks.
   - Checkbox completes/uncompletes directly.
   - Row stays minimal.

2. Big task
   - Has one or more subtasks.
   - Parent represents the goal/container.
   - Subtasks are the real actionable steps.
   - Parent completion is calculated automatically from subtasks.
   - Parent checkbox does NOT mark all subtasks complete.
   - Parent checkbox expands/collapses instead, to prevent accidental completion.
   - Progress bar shows subtask completion.

Current important behavior:
- Incomplete tasks stay above completed tasks.
- Subtasks also sort incomplete first.
- Only one task expands at a time.
- Expanded mode shows edit/delete and subtask management.
- Collapsed rows stay visually calm.

Important code shape:

    function syncTodo(todo) {
        const subtasks = sanitizeSubtasks(todo?.subtasks);
        const hasSubtasks = subtasks.length > 0;
        const done = hasSubtasks ? subtasks.every(subtask => subtask.done) : !!todo?.done;
        return { todoId, task, done, expanded, createdAt, subtasks };
    }

    function toggleTodo(index) {
        const todoSubtasks = sanitizeSubtasks(todo.subtasks);
        if (todoSubtasks.length > 0) {
            setExpandedExclusive(index, !todo.expanded);
            return;
        }
        patchTodo(index, { done: !todo.done });
    }

Resource impact:
- Light.
- Uses local JSON.
- Saves after changes with a short debounce timer.
- No network.

Potential suggestions:
- Keep it simple.
- Do not re-add priorities/notes/categories unless absolutely necessary.
- If a new AI suggests many tags or scheduling systems, that conflicts with the current design.
